# HD-DATA-CONTRACT-1.1：日线收盘信号与滞后一日收盘竞价成交

> [方法选择｜C] 修订日期：2026-09-10（Asia/Shanghai）。本文件只覆盖[`data_contract_v1.md`](data_contract_v1.md)中与P00信号—成交时序相关的条款；其余字段、来源、清理、公司行动和审计要求完全继承v1.0。
>
> [已观察事实｜A] 对应策略协议为[`preregistration_v1.1_daily_close_lagged.yaml`](../experiments/HD-ANCHOR-001/preregistration_v1.1_daily_close_lagged.yaml)。原v1.0 Tick契约保留给L4，不被删除。

## 1. 时间语义

[方法选择｜C] 对每个交易日T，`close_t`表示T日收盘集合竞价完成后形成的未复权正式收盘价。T日的信号只能在`close_t`可得之后产生，最早成交日为下一有效交易日T+1。

```text
T日收盘后   close_t + PIT Dhat_t → 信号/确认/目标仓位
T+1 14:57   提交已经确定的收盘竞价保护限价订单
T+1 15:00   final_close_t+1 → 成交或UNFILLED
```

[方法选择｜C] `final_close_t+1`是成交结果字段，不是T日信号字段。任何实现若在同一行把`close_t`同时写作信号价和成交价，必须被审计器判为`SAME_DAY_CLOSE_LOOKAHEAD`。

## 2. P00所需价格和可成交字段

| 字段 | 要求 |
|---|---|
| [方法选择｜C] `session_date` | 上交所交易日，来自版本化权威日历 |
| [方法选择｜C] `close` | 未复权最终收盘价；保存价格来源、版本、检索时间和原始行定位 |
| [方法选择｜C] `pre_close` | 原始提供或经连续有效交易日派生，并标记派生方法 |
| [方法选择｜C] `trade_status` | 正常、停牌、不可交易等；缺失不得默认正常 |
| [方法选择｜C] `limit_up`、`limit_down` | 交易日对应的权威价格限制；不得只凭固定涨跌幅猜造 |
| [方法选择｜C] `source`、`version`、`raw_record_id` | 可追溯至原始文件、供应商/接口版本和行号或唯一键 |

[已知限制｜A] 当前QMT原始日线已具备`datetime`、OHLC、成交量、成交额、`adjust=none`和`source=xtquant`，但尚缺`trade_status`、涨跌停价、来源版本和行级来源ID；这些缺口仍须通过清理和副源核验解决。

## 3. 不再作为P00硬门禁的数据

[方法选择｜C] 历史`[14:57,15:00)` Tick、真实接收时间、虚拟参考价及盘口不再是P00的必要输入。它们仍应保留为L4执行审计、代理价—最终价差分析和未来`HD-EXEC-002`的数据契约。

[已知限制｜C] 不要求Tick不等于允许把收盘价用作同日可见信号。P00通过一日滞后保证日线信号与尾盘成交的因果顺序。

## 4. 仍然不可省略的L2门禁

[方法选择｜C] 下列任一项未验收通过时，不得将日线执行结果称为L2：历史时点分红预期及180日有效性、真实现金分红和公司行动、权威交易日历、历史费税表、未复权价格及可交易状态、独立价格副源、逐日账户恒等式和完整数据版本清单。

[已观察事实｜B] 已发现候选公司行动表[`600900_cash_dividend_actions_2004_2026.csv`](600900_cash_dividend_actions_2004_2026.csv)：30条记录的`record_date`、`ex_date`、`pay_date`和`cash_dividend_per_share`均非空，且每条含主、副来源字段。它可进入阶段5正式审计，但在权益类别、差异化分红、税务版本、来源可访问性和账户入账恒等式核验前，不视为已验收的L2输入。

[计算结果｜B] 现有六条年度分红候选按180日规则在2021-05-06至2026-09-09的QMT观测交易日覆盖率约54.07%，低于预注册80%门槛；本修订不改变该结果。
