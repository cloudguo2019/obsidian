## 1. 拟确认的单项修订范围

[方法选择｜提案] 在Popper研究层加入**完整账户的下单准入保护、真实接收时钟、产品结算与费用预留**。MA20、20/60动量排名、前5新买/前15保留、category/group、最多3只、单只20%、总60%、5000固定执行基数、front_ratio当日锚点和集合竞价窗口沿用当前确认。旧工程保留为观察规格；研究实现需另带版本，不得宣称精确复现旧代码。

[已知限制] 新保护可能拒绝旧代码允许的订单，改变换仓时点、实际敞口和成交集合，因此需要用户确认后才能成为研究基线；它不是仅改标签。不能把保护前后结果归因为MA或MACD。

## 2. 全账户准入与未成交

[方法选择｜提案] 每次BUY准入读取同一as-of账户快照：可用cash、broker frozen_cash、全持仓/可卖量、在途BUY及已确认成交、产品/category/group版本。只统计已确认成交释放的卖出仓位和现金；未成交SELL不冲减持仓敞口，也不增加可用现金。broker已冻结金额不能再次从cash重复扣除。

[方法选择｜提案] 只要ETF轮动已有计划退出持仓尚未完成，暂停当日所有新的BUY，SELL仍按原目标和可卖量处理。保持集合竞价single_submit，不等待、撤单或追单；如果该窗口结束前退出未确认，最早在下一个获准决策/执行窗口重新生成买入候选。排序为卖单先提交只能帮助审计，不能代替成交确认。

[方法选择｜提案] 无计划退出时，BUY还须满足账户数量、symbol/category/group和总敞口保护。未知分类持仓默认保留，不主动清仓；只要无法证明新BUY不会违反账户约束，拒绝新BUY并记录原因。已有越限或因市场变动漂移单独记异常、阻止增仓，沿原目标处理可卖仓位；本提案不引入盘中强制止损或未知持仓清仓。

```text
A = min(5000, actual_account_equity)
H = 已确认正持仓symbol ∪ 活跃/接收不明的BUY symbol ∪ 拟BUY symbol
N = |H| ≤ 3

E_projected = 当前持仓未复权市值
            + 未完成BUY的保守成交名义额
            + 拟BUY份数 × 买入委托限价
            （不抵扣未成交SELL）
A_conservative = min(5000, actual_account_equity - 本次尚未计入的费用上界)
E_projected / A_conservative ≤ 0.60
symbol/category/group约束同时通过
```

[已知限制] 这是下单准入和订单导致的峰值风险保护。市价变动、报价陈旧或不明回报仍可使实际敞口漂移；不得把规则描述成任何瞬间都保证60%。必须报告实际峰值、漂移与阻单，不靠隐藏现金差异评价趋势效果。

## 3. 委托数量和费用

[方法选择｜提案] 保留买涨停/卖跌停限价换算与100份整手。先用原目标得候选份数，再递减整手，直到满足风险及 `买入增量×限价+fee_upper_bound≤可用现金-未在broker冻结的在途现金预留`。只有已证实broker冻结的现金才解除本地预留；接收不明保留，恢复时先对账而非自动释放。

[方法选择｜提案] commission/minimum/费用计取与分位舍入方式须明确版本。当前观察值万一、ETF最低0.1元只用于合成诊断，不是用户真实券商费率。现金收益不擅自冻结为0；若采用0收益近似或固定其他经济模型，另行记录确认。没有真实原价、分配、可用时钟和费用时，研究输出只能留在L0。

[待办事项] 用户需提供可核验的ETF买卖佣金、最低佣金及是否存在其他费用；不需要提供账户号。当前配置中4个SDK路径在本机均缺失，随附Python也未定位到xtquant；需要新SDK/原始数据位置才能进行供应商对账。

## 4. 时钟契约

[方法选择｜提案] 每次实际查询使用时区感知字段：`request_started_at`在调用前、`received_at`在返回后、供应商`quote_at`保留原值。名义排名14:57；实际τ是完成该次信号输入接收后的截止，目标另记`target_generated_at`。历史/实时共用价格构造函数，满足 `quote_at≤received_at≤τ≤target_generated_at`，只用τ已知已生效事件。若供应商时钟确实偏离，先校准并冻结映射，不能为了保留报价放宽前视检查。

[方法选择｜提案] 整池排名同一τ，非停牌标的输入不齐则不生成目标。提交重新采样，逐symbol记录自己的接收/生成/提交时间，检验报价年龄≤5秒、状态18及窗口 `[14:57:30,15:00:00)`；不得因调用耗时把窗口外订单算作窗口内。旧captured_at/event_time保留原字段，不补写无法观察到的真实接收时间。

[已知限制] 正确接收时间本身是技术修复；改动准入和费用预留会改变订单集合。本稿合并描述但须分别记录修订原因，后续趋势实验固定这些版本。

## 5. 产品结算与经济账户

[方法选择｜提案] 用逐symbol产品结算规则、所属交易所日历及真实broker可卖量。T+1只在适用的下一可执行交易日解锁；T+0仅对已核验产品生效。不直接把上交所日历复用于深交所/跨境产品；休市没有订单机会或零收益假设。

[方法选择｜提案] 总现金余额须拆出可用/冻结/其他不可用现金，账户恒等式逐事件核验：

```text
cash_end = cash_begin - buy_gross + sell_gross - fees
           + distributions_paid + cash_return + 外部资金变动
equity_end = 全部现金余额 + 真实未复权持仓市值 + 已解释其他资产/应收
```

[方法选择｜提案] 分配按权益与支付日期确认持有权利、应收与到账，原价估值，不将复权信号收益再次入账。外部入出金及shadow balance_adjustment明确标记，不能计作策略收益；重启不得无日志地重置研究账户。缺少分配不能假称经济完整。

## 6. 确认后的实施与验收清单

[待办事项] 仅在研究层新建保护原型和L0测试，至少涵盖：

1. 未成交/部分成交退出、T+1不可卖时新买关闭；仅重排SELL不能误开。
2. 全账户未知持仓、在途BUY、category/group冲突、接收不明、重复回报/重启不重复下单。
3. 5000上限、资产不足、手续费减少整手、broker冻结与本地预留不双扣。
4. 查询延迟、真正received_at、每symbol提交窗口、晚到/陈旧/未来报价、整池失败关闭。
5. T+0/T+1、周末/节假日/跨市场日历、原价估值、分配应收/到账、现金与权益逐事件对账。

[方法选择] 新测试通过只可证明研究原型机械完整；供应商因子方向/精度/事件完整性、真实front_ratio对账、完整原价/回报与实际费用仍需验收。不把合成L0升级成L1/L2，不提前进入阶段2或正式批次。
