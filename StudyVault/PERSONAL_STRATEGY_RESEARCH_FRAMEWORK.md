# 个人策略研究框架

> 以高股息类债策略与 ETF 轮动策略为案例
>
> 版本：v0.1  
> 状态：研究方法基线  
> 适用范围：从策略想法、历史验证到仿真和小资金上线的完整研究过程

## 0. 文档定位

这套框架的目标不是寻找一套对所有市场都有效的“万能策略”，而是建立一套适合个人投资者、可以反复使用和持续改进的研究方法。

高股息与 ETF 是两个案例，不是框架本身：

- 高股息案例用于研究估值、现金流、库存管理和网格执行。
- ETF 案例用于研究趋势、横截面选择、买卖信号和组合管理。
- 将来研究其他策略时，应继续复用同一套问题定义、数据契约、实验设计、评价和上线流程。

一项完整研究最终应留下三类成果：

1. **证据**：数据、回测、样本外和仿真结果能否支持原始假设。
2. **决策**：接受、继续观察、修改还是淘汰。
3. **知识**：这次研究对未来其他策略有什么可复用的认识。

核心流程如下：

```text
个人目标与约束
    ↓
研究问题与可证伪假设
    ↓
策略分层与数据契约
    ↓
基准策略
    ↓
单变量实验
    ↓
组合实验
    ↓
滚动样本外与压力测试
    ↓
仿真和小资金验证
    ↓
接受 / 观察 / 修改 / 淘汰
    ↓
沉淀为下一轮研究知识
```

# 第一部分：通用研究框架

## 1. 先定义“适合自己”

个人策略研究的起点不是指标，而是投资者自身的目标和约束。同一套策略对不同投资者可能得出完全不同的结论。

开始研究前，应先写清楚以下内容：

| 维度 | 需要回答的问题 |
|---|---|
| 收益目标 | 追求绝对收益、相对收益、现金流，还是资本长期增长？ |
| 风险预算 | 可以接受多大最大回撤、单年亏损和回撤持续时间？ |
| 资金属性 | 是否长期不用、是否存在提款需求、是否需要保留现金？ |
| 持仓偏好 | 偏好集中还是分散，能否接受长期空仓或长期满仓？ |
| 交易频率 | 愿意每天处理、每周处理，还是只做低频决策？ |
| 执行能力 | 能否在固定时间盯盘、维护数据并处理异常订单？ |
| 心理约束 | 更难接受浮亏、踏空、频繁止损，还是长期无交易？ |
| 维护成本 | 愿意投入多少时间做数据更新、复核和策略迭代？ |

研究目标最好写成一个带约束的优化问题，而不是“收益越高越好”。例如：

```text
在最大回撤不超过个人风险预算、交易频率可维护的前提下，
提高长期净收益和决策一致性。
```

每类策略只能指定一个首要目标，再配置若干风险护栏。例如：

- 首要目标：提高样本外 Calmar。
- 风险护栏：最大回撤不超过基准、年换手率不超过上限、双倍成本后仍可接受。

不要在看到结果后临时更换首要指标。

## 2. 从想法变成可证伪假设

一个策略想法至少要形成下面的因果链：

```text
市场或资产存在什么特征
→ 为什么会形成可持续行为
→ 哪个变量能够观测这种行为
→ 如何把变量转成决策
→ 扣除成本后为什么仍可能有收益或风险改善
```

推荐使用以下假设模板：

```text
在【适用市场状态】下，
由于【经济、行为或制度原因】，
【可观测变量】能够识别【目标状态】，
因此采用【决策规则】相对【基准策略】
应当改善【一个首要指标】，同时不突破【风险护栏】。

如果在【预先规定的样本外或压力条件】下没有改善，
则该假设被否定或降级为观察状态。
```

好的假设应当：

- 能说明潜在收益来自哪里，而不只是描述历史相关性。
- 能被一个相对简单的实验否定。
- 明确适用边界，不要求任何市场状态下都赚钱。
- 先确定失败条件，再运行回测。

## 3. 将策略拆成独立研究层

任何策略都应拆成若干独立层。每次实验原则上只改变一层，避免无法解释收益变化来自哪里。

| 层级 | 研究内容 | 典型问题 |
|---|---|---|
| 1. 标的层 | 可投资范围和准入条件 | 买什么，何时进入或离开研究池？ |
| 2. 数据层 | 价格、基本面、成交量和外部数据 | 在决策时点实际能看到什么？ |
| 3. 状态层 | 估值、趋势、波动和市场环境 | 当前处于什么状态？ |
| 4. 信号层 | 买入、卖出、持有和再平衡条件 | 什么变化才触发行动？ |
| 5. 仓位层 | 单标的仓位、组合仓位和现金 | 应该买多少、最多承担多少风险？ |
| 6. 执行层 | 下单时点、价格、成交和成本 | 理论信号能否按预期成交？ |
| 7. 风控层 | 暂停、降仓、退出和人工复核 | 哪些异常可以覆盖正常策略信号？ |

需要特别区分三个概念：

- **状态**：当前是否处于有利环境，例如 MACD 多头状态。
- **触发**：状态是否刚刚发生变化，例如当日金叉。
- **目标仓位**：状态或触发发生后，最终希望持有多少。

把三者混在一起，是策略规则快速膨胀和难以解释的常见原因。

## 4. 建立数据契约

数据契约规定回测在每个历史时点允许看到什么、如何计算以及何时成交。没有数据契约，收益指标没有研究意义。

### 4.1 时间可得性

每个字段至少应记录：

```text
event_time       数据对应的经济事件时间
available_time   数据在现实中可以获得的时间
effective_time   策略允许开始使用的时间
source           数据来源
version          数据版本
```

策略在时间 `t` 只能使用 `available_time <= t` 的信息。

重点检查：

- 财报和分红数据不能按报告期结束日提前使用。
- 成分股、ETF 池和上市状态必须按历史时点重建。
- 修订后的数据不能无标记地覆盖当时实际公布值。
- 计算滚动指标时只能使用当前及以前的数据。

### 4.2 价格与公司行动

不同任务可以使用不同价格序列，但必须明确分工：

- 实际成交和现金股息率：使用真实未复权价格。
- 连续收益率和技术指标：通常使用适当复权后的连续价格。
- 现金分红：在账户现金流中单独处理时，不能再通过复权收益重复计入。
- 除权、拆并股、停牌和涨跌停：需要进入成交与持仓模型。

### 4.3 信号与成交时序

必须显式写出：

```text
观察数据截止时点
→ 计算信号时点
→ 提交订单时点
→ 模拟成交时点
→ 使用的成交价格
```

例如，使用当日完整收盘价计算的信号，默认只能在下一个可交易时点成交。若希望参加当日收盘集合竞价，就必须使用竞价提交前已经可见的数据，并在回测中采用一致的历史数据与成交模型。

### 4.4 数据质量门槛

正式回测前至少检查：

- 时间是否单调、是否存在重复记录和缺失交易日。
- OHLC、成交量、成交额和复权因子是否合理。
- 指标暖机期是否完整。
- 标的上市、退市、停牌和不可交易状态是否正确。
- 数据调整口径与配置是否一致。
- 样本起止日期是否覆盖足够多的市场阶段。

数据审计不通过时，只能进行机械测试，不能得出投资有效性结论。

## 5. 区分四种研究成熟度

同一个“回测”可能回答完全不同的问题，应明确当前处于哪一层。

| 层级 | 名称 | 回答的问题 | 可以得出的结论 |
|---|---|---|---|
| L0 | 规则验证 | 公式、状态转换和订单数量是否正确？ | 代码是否符合设计 |
| L1 | 机械回测 | 策略能否在历史行情上完整运行？ | 流程是否连通 |
| L2 | 经济有效性回测 | 使用当时可得数据和真实现金流后是否优于基准？ | 假设是否得到历史支持 |
| L3 | 样本外与稳健性 | 换时期、参数、成本和延迟后是否仍成立？ | 是否可能具备可迁移性 |
| L4 | 可执行性验证 | 仿真和小资金成交是否接近模型？ | 是否具备上线条件 |

不能用 L0 或 L1 的漂亮收益替代 L2 至 L4 的证据。

## 6. 先建立基准，再研究改进

任何新变量都必须相对基准评价。通用基准可以分成三层：

1. **资产基准**：现金、买入持有、等权持有或合适的市场指数。
2. **风险匹配基准**：与策略保持相似平均仓位、最大仓位和再平衡频率。
3. **当前策略基准**：尚未加入新变量的最简单可运行版本。

比较时优先保证以下条件一致：

- 初始资金和现金流。
- 可投资标的范围。
- 最大组合仓位和单标的仓位。
- 信号与成交时点。
- 交易成本和不可成交规则。

如果策略只有60%平均仓位，就不能只把它和100%满仓指数的收益率直接比较。需要同时报告风险匹配结果或单位敞口收益。

## 7. 设计单变量实验

推荐顺序：

```text
无策略基准
→ 最简单策略基准
→ 单一状态变量
→ 单一买入触发
→ 单一卖出触发
→ 仓位规则
→ 执行优化
→ 少量有逻辑依据的组合
```

每次实验应遵循：

- 一个实验只回答一个主要问题。
- 除被研究变量外，其余数据、成本、仓位和规则保持不变。
- 参数范围在运行前确定。
- 所有尝试都登记，不能只保留最好结果。
- 首先寻找稳定的平台区域，而不是单个最优参数。
- 组合实验只能使用已经在单变量实验中表现稳定的组件。

实验卡片建议包含：

```yaml
experiment_id:
created_at:
hypothesis:
falsification_condition:
baseline:
changed_component:
fixed_components:
data_version:
universe_version:
signal_time:
fill_rule:
cost_model:
parameters:
development_period:
validation_period:
locked_test_period:
primary_metric:
risk_guardrails:
result_summary:
decision:
lessons:
```

## 8. 使用时间顺序的样本外验证

金融数据不是独立同分布样本，不应随机打乱后切分训练集和测试集。

推荐采用时间顺序验证：

1. **开发集**：提出规则和限制参数范围。
2. **验证集**：选择少量候选方案。
3. **滚动样本外**：观察不同时间窗口的稳定性。
4. **最终锁定集**：参数完全冻结后只运行一次。

一个可复用的滚动方案是：

```text
过去3年：研究和参数选择
随后6个月：样本外验证
每6个月向前滚动一次
最后12个月：最终锁定测试
```

窗口长度应根据策略频率调整。低频策略的关键不是日历长度，而是是否覆盖足够多的独立决策、价格周期和市场状态。

如果最终锁定集已经被反复查看，它就不再是样本外数据。此时应将后续仿真或未来新增数据作为新的锁定样本。

## 9. 建立多维评价体系

不要用单一收益率或单一 Sharpe 判断所有策略。先为策略选择一个首要指标，再使用其他维度作为护栏和诊断。

### 9.1 收益

- 扣除全部成本后的总收益和年化收益。
- 相对风险匹配基准的超额收益。
- 月度、年度和滚动区间收益。
- 现金分红、价差收益和其他收益来源的归因。

### 9.2 风险

- 最大回撤及回撤修复时间。
- 最差单日、单周、单月和单年表现。
- 下行波动、尾部损失和连续亏损。
- 单标的、行业、主题和风险因子的集中度。

### 9.3 资金效率

- Calmar、Sharpe 等风险调整指标。
- 平均和峰值资金占用。
- 单位平均敞口收益。
- 现金闲置比例和资金容量。

### 9.4 交易质量

- 交易次数、换手率和平均持有期。
- 毛收益、净收益和总交易成本。
- 成本占毛收益的比例。
- 滑点、未成交、部分成交和追价情况。
- 信号触发后短期反向退出的比例。

### 9.5 稳健性

- 各滚动样本外窗口的通过率。
- 参数邻域是否形成稳定平台。
- 收益是否集中在少数年份、标的或交易。
- 成本、延迟和不利成交压力下的表现。
- 牛市、熊市、震荡和高低波动阶段的差异。

## 10. 压力测试与证伪

候选策略至少进行以下压力测试：

| 压力类型 | 测试方式 |
|---|---|
| 成本压力 | 基础成本、2倍成本、3倍成本 |
| 成交压力 | 成交价格向不利方向偏移，模拟更大滑点 |
| 延迟压力 | 信号延迟一根或多根 K 线执行 |
| 参数压力 | 检查相邻参数，而不是只看最优点 |
| 起点压力 | 改变回测开始日期和首次建仓日期 |
| 数据压力 | 缺失数据、异常值、停牌和不可交易处理 |
| 市场状态 | 分牛、熊、震荡、高波动和低波动阶段 |
| 组合压力 | 单一标的、行业或主题突然失效 |

建议的通用通过条件：

1. 多数滚动样本外窗口相对基准改善首要指标。
2. 最差窗口不突破个人风险预算。
3. 双倍成本和一根 K 线延迟后仍有可接受结果。
4. 邻近参数表现相近，而不是只有一个参数点有效。
5. 结果不依赖极少数交易、年份或标的。
6. 规则可以用简洁语言解释，并能在现实中执行。

未通过时，根据证据作出明确分类：

- **淘汰**：核心假设在样本外被否定。
- **修改**：逻辑可能成立，但数据、执行或仓位设计有明确缺陷。
- **观察**：样本数量不足，暂时不能判断。
- **接受**：达到预设门槛，可以进入仿真阶段。

## 11. 从回测走向真实执行

上线采用逐级晋升：

```text
历史回测
→ 仿真信号
→ 仿真成交与账户对账
→ 极小资金
→ 限额运行
→ 正常策略额度
```

仿真阶段主要验证：

- 实时数据与回测数据是否一致。
- 信号生成时点是否符合设计。
- 实际可成交价格与回测假设的差距。
- 订单拒绝、部分成交、T+1和最小交易单位。
- 持仓、资金、分红和费用能否每日对账。
- 人工复核、暂停和恢复流程是否清晰。

上线后也不能停止研究。应持续监控：

- 实际与模型滑点差异。
- 信号频率和历史分布是否漂移。
- 收益来源是否改变。
- 数据字段、市场制度和交易接口是否变化。
- 是否触发预先规定的降仓、暂停或论文重审条件。

## 12. 研究档案与知识积累

建议逐步建立如下研究目录：

```text
research/
├─ README.md                 # 当前研究地图
├─ hypotheses/              # 研究假设卡
├─ baselines/               # 基准定义和结果
├─ experiments/             # 每次实验的配置和结论
├─ decisions/               # 接受、淘汰和变更记录
├─ datasets/                # 数据版本与审计摘要
└─ dashboards/              # 样本外和仿真跟踪
```

实验编号建议使用：

```text
<策略>-<研究层>-<序号>

例如：
HD-ANCHOR-001
HD-EXEC-002
ETF-REGIME-001
ETF-EXIT-003
```

每轮研究结束时，应回答三个问题：

1. 哪条假设得到了什么级别的证据？
2. 哪些结果只是特定案例，哪些可以推广？
3. 下一项实验是否真的能增加信息，而不只是继续搜索更好看的参数？

# 第二部分：案例一——高股息类债策略

## 13. 案例定位

高股息案例用于打磨以下通用问题：

- 如何把基本面估值转换成目标仓位。
- 如何区分长期持仓与可交易库存。
- 如何组合基本面价格锚与市场行为价格锚。
- 如何正确处理历史分红预期、除权和现金分红。
- 如何评价网格交易到底增加了收益，还是仅增加了交易。

本案例将“高量价格”定义为成交量分布中的成交密集价，包括 POC 和 HVN。

## 14. 研究假设

### H1：股息率价格锚具有仓位管理价值

在分红能力相对稳定的前提下，投资者对股息率存在可观察的要求区间，因此：

```text
股价越低、前瞻股息率越高
→ 允许持有的目标仓位越高

股价越高、前瞻股息率越低
→ 只保留更低的长期核心仓位
```

股息率价格锚为：

```text
yield_anchor_price = 当时可知的预期年度每股分红 / 要求股息率
```

### H2：成交量密集价具有执行价值

历史成交密集区反映较多持仓成本和市场记忆，可能形成阶段性支撑、阻力或换手区域，因此它可能改善网格成交位置，但不直接决定资产是否值得长期持有。

### H3：分层组合优于简单混合

推荐的职责划分是：

- 股息率锚决定增减仓方向与理想库存。
- 成交量锚决定网格挂单价和执行时机。
- 基本面闸门决定是否暂停加仓、全面复核或退出。
- 核心仓不因普通价格和技术信号自动卖出。

暂不使用“股息率价格和成交量价格加权平均”的黑箱方案。

## 15. 策略分层映射

| 通用层级 | 高股息案例中的实现 |
|---|---|
| 标的层 | 分红可持续、现金流可理解、资本开支和治理风险可接受的公司 |
| 数据层 | 未复权价格、复权连续价格、历史分红预期、真实分红现金流、成交量分布 |
| 状态层 | 前瞻股息率档位、基本面闸门、价格回撤和成交量节点 |
| 信号层 | 相邻仓位状态之间的买入或卖出触发 |
| 仓位层 | 核心仓、增强仓、机动仓和单次100股调整 |
| 执行层 | 收盘集合竞价或下一交易时点，成交量节点附近挂单 |
| 风控层 | `NORMAL / REVIEW / STOP_ADD / EXIT` |

## 16. 数据契约

经济有效性回测至少需要：

```text
datetime
symbol
raw_price
adjusted_price
expected_annual_dividend_per_share
dividend_estimate_as_of
dividend_available_time
cash_dividend
ex_date
pay_date
volume_profile_inputs
```

关键约束：

- 股息率只能使用当时已经公开或已经形成的分红预期。
- 未复权价格用于股息率和真实成交。
- 复权连续价格可用于成交量结构和波动指标，再映射回当期真实价格。
- 现金分红单独进入账户现金流，避免重复计算。
- POC/HVN 必须使用决策时点以前的数据滚动计算。
- 日线 OHLCV 只能近似成交量分布，优先使用小时或更细粒度数据。

现有设计文档已经明确区分机械回测和有效历史回测，参见 [高股息策略设计](HIGH_DIVIDEND_BOND_POSITION_STRATEGY_DESIGN_v1.0.md#15-回测设计与限制)。

## 17. 基准与实验矩阵

| 实验 | 规则 | 主要回答的问题 |
|---|---|---|
| HD-BASE-000 | 核心仓＋现金不动 | 最低交易基准 |
| HD-BASE-001 | 等资金静态持有 | 动态仓位是否真正创造增量 |
| HD-ANCHOR-001 | 现有股息率档位＋滞回 | 估值锚是否独立有效 |
| HD-ANCHOR-002 | 只按成交量密集价做网格 | 市场结构锚是否独立有效 |
| HD-ANCHOR-003 | 股息率定库存＋HVN定执行 | 两种价格锚能否互补 |
| HD-EXEC-001 | 下一交易日开盘成交 | 保守执行基准 |
| HD-EXEC-002 | 历史盘中数据模拟收盘竞价 | 真实执行是否改善或恶化结果 |
| HD-ANCHOR-004 | 固定股息率门槛改为相对利率门槛 | 后续研究，不进入第一轮 |

成交量锚的第一轮参数应保持有限：

- 回看窗口：60、120、250个交易日。
- 分箱宽度：固定百分比或 ATR 归一化宽度。
- 更新频率：每周或每月。
- 可接受节点距离：以 ATR 表示。
- 未成交超时：到期后取消并重算，不追价。

## 18. 首要指标与证伪条件

推荐首要指标：

```text
相对等资金、等平均敞口静态持有的含分红净增量收益
```

风险与诊断指标：

- 最大回撤和修复时间。
- 网格已实现收益与持仓浮动损益。
- 交易成本占网格毛收益比例。
- 平均、最高和最低库存。
- 现金闲置比例。
- 上涨阶段因减仓造成的机会损失。
- 收益是否集中在少数价格震荡阶段。

初步证伪条件：

- 扣除真实成本后，网格长期不能超过风险匹配静态持有。
- 增量收益只来自未来分红信息或不现实成交价格。
- 双倍成本或一日延迟后结果消失。
- 组合锚没有优于更简单的股息率单锚。
- 动态仓位显著放大下跌库存和账户回撤。

## 19. 对当前工程的应用

当前工程已经具备：

- 股息率档位和相邻持仓滞回状态机。
- 核心、增强、机动仓设计。
- 基本面人工闸门。
- 回测、日志和专属报告入口。

因此现有规则适合作为 `HD-ANCHOR-001` 基准，而不是最终策略。

进入经济有效性研究前需要补齐：

1. 历史时点分红预期序列。
2. 现金分红到账和除权处理。
3. 成交量分布及 POC/HVN 计算。
4. 回测与收盘集合竞价执行语义的一致性。
5. 更长时期和多个市场状态的样本外验证。

相关配置参见 [high_dividend_bond_config.json](../sartre_core/config/high_dividend_bond_config.json)。

# 第三部分：案例二——ETF 轮动与 MACD

## 20. 案例定位

ETF 案例用于打磨以下通用问题：

- 如何区分横截面选择和单标的趋势判断。
- 如何区分趋势状态、趋势触发和退出条件。
- 如何避免多个ETF、参数和规则带来的数据挖掘。
- 如何处理历史ETF池、上市时间和幸存者偏差。
- 如何评价趋势策略的踏空、反复止损和组合换手。

## 21. 研究假设

### H1：轮动排名负责“选谁”

ETF 的相对动量、风险和流动性指标用于在可投资池中比较候选标的，回答当前优先持有什么。

### H2：MACD 负责“是否处于可持有趋势”

MACD 不直接替代轮动排名，而是作为单标的趋势状态或触发变量，减少在明显弱趋势中持仓。

### H3：MACD 状态可能比当日金叉更适合轮动

某只ETF可能在金叉发生若干日后才进入轮动排名前列。如果买入必须与金叉发生在同一天，策略可能错过已经建立的趋势。因此第一轮优先研究：

```text
排名满足条件 AND DIF > DEA
```

而不是直接规定：

```text
排名满足条件 AND 当日恰好金叉
```

金叉方案保留为对照实验。

## 22. 策略分层映射

| 通用层级 | ETF 案例中的实现 |
|---|---|
| 标的层 | 历史时点可交易的ETF池、上市时间、流动性和类别约束 |
| 数据层 | 复权日线、真实成交价、成交量、成交额和历史ETF池 |
| 状态层 | MACD状态、均线状态、波动状态和市场趋势 |
| 信号层 | 金叉、死叉、排名进入与退出、连续确认 |
| 仓位层 | 最多持有数量、单标的仓位、总仓位和类别上限 |
| 执行层 | 调仓频率、下一交易时点成交、换仓先卖后买 |
| 风控层 | 趋势失效、排名退出、组合集中和数据异常 |

## 23. 数据契约

ETF 回测必须做到：

- 按历史时点重建ETF池，不能直接倒用今天的存续列表。
- 上市前不可进入候选池；上市后必须满足完整暖机期。
- 退市、停牌和不可交易状态必须保留。
- 技术指标使用连续价格，成交使用当时可交易价格。
- 当日收盘指标默认在下一可交易时点执行。
- 排名、趋势和组合目标必须全部使用同一决策截止时间。

当前本地ETF数据的较早共同起点大致在2020年，后续上市ETF历史更短。因此研究时需要同时报告：

- 固定成熟ETF子样本结果。
- 按历史准入动态扩展ETF池的结果。
- 新ETF暖机和进入候选池的处理方式。

## 24. 基准与实验矩阵

现有ETF策略使用均线趋势过滤、20/60日动量评分、买入前5和持有保留到前15，可作为当前策略基准。

| 实验 | 买入条件 | 卖出条件 | 主要问题 |
|---|---|---|---|
| ETF-BASE-000 | 风险匹配的宽基或ETF等权组合 | 定期再平衡 | 被动基准 |
| ETF-BASE-001 | 当前MA趋势＋轮动排名 | 当前退出规则 | 当前策略基准 |
| ETF-REGIME-001 | 排名前5且 `DIF > DEA` | 死叉或当前退出规则 | MACD状态是否优于MA状态 |
| ETF-ENTRY-001 | 排名前5且当日金叉 | 死叉 | 新鲜交叉是否必要 |
| ETF-REGIME-002 | 排名前5、`DIF > DEA` 且 `DIF > 0` | 死叉、跌破长期均线或排名退出 | 强趋势过滤是否改善回撤 |
| ETF-CONFIRM-001 | ETF-REGIME-002连续两日成立 | 同ETF-REGIME-002 | 确认是否减少假信号 |
| ETF-REBAL-001 | 固定信号，日频排名 | 固定退出 | 当前调仓频率基准 |
| ETF-REBAL-002 | 固定信号，周频排名 | 固定退出 | 降低频率能否改善净收益 |

第一轮固定 MACD `12/26/9`，暂不优化参数。只有确认 MACD 变量相对当前均线基准存在稳定增量后，才研究少量预先声明的邻近参数。

## 25. 首要指标与证伪条件

推荐首要指标：

```text
相对当前MA轮动基准、在相同组合仓位下的样本外Calmar改善
```

风险与诊断指标：

- 净年化收益和最大回撤。
- 平均组合仓位和单位敞口收益。
- 年换手率和总交易成本。
- 金叉后5日、10日内反向退出的比例。
- 趋势行情参与率和长期空仓比例。
- 收益对少数ETF、行业、主题和月份的集中度。
- 排名变化、MACD退出和风控退出的收益归因。

初步证伪条件：

- MACD 版本没有优于当前MA轮动基准。
- 结果主要来自仓位降低，而风险匹配后没有增量。
- 优势只集中在某个ETF或单一市场阶段。
- 换手与成本吞噬了毛收益。
- 延迟一天或改变相邻参数后结果快速消失。
- 金叉买入造成大量已经错过的趋势和频繁反向退出。

## 26. 对当前工程的应用

当前工程已经具备两项可以复用的能力：

- [ETF轮动核心](../sartre_core/strategies/etf_rotation_core.py)：ETF池、均线过滤、动量排名和目标仓位。
- [MACD核心](../sartre_core/strategies/macd_core.py)：标准12/26/9金叉和死叉信号。

研究时不应简单把 `strategy_id` 从 `etf_rotation_core` 改成 `macd_core`，因为这样会丢失ETF池、排名、类别限制和组合约束。更适合的方法是在 ETF 轮动研究层中增加 MACD 状态和触发字段，并通过实验配置切换。

进入有效研究前需要优先处理：

1. 将当前很短的回测日期扩展到多个市场阶段。
2. 统一研究数据的日线前复权口径与回测数据配置。
3. 建立历史时点ETF池或明确标记“当前ETF池回看实验”。
4. 为 MACD 增加明确、可记录的实验参数配置。
5. 输出换手、成本、信号反转和样本外分段指标。

相关配置参见 [etf_rotation_config.json](../sartre_core/config/etf_rotation_config.json)。

# 第四部分：用两个案例打磨通用框架

## 27. 案例之间的共同结构

| 研究维度 | 高股息案例 | ETF案例 | 可推广认识 |
|---|---|---|---|
| 潜在优势来源 | 现金流估值与价格波动 | 趋势延续与相对强弱 | 先解释优势来源，再选择指标 |
| 状态变量 | 前瞻股息率、基本面闸门 | MACD、均线和波动 | 状态不等于交易触发 |
| 选择问题 | 是否值得长期持有 | 当前优先持有哪只ETF | 标的选择与择时应分层 |
| 仓位问题 | 核心、增强、机动库存 | 单标的和组合权重 | 仓位规则是独立研究对象 |
| 执行问题 | 成交量节点和集合竞价 | 换仓顺序、频率和下一时点成交 | 执行不是回测后的附属模块 |
| 主要数据偏差 | 未来分红、除权和现金流 | 幸存者偏差和上市时间 | 所有策略都需要时点数据契约 |
| 合理基准 | 静态持有和股息率单锚 | 当前MA轮动和风险匹配组合 | 新变量必须相对简单基准评价 |
| 主要失败方式 | 库存堆积、踏空上涨、成本侵蚀 | 震荡反复、频繁换手、趋势滞后 | 失败模式应在研究前定义 |

## 28. 从案例中反向更新框架

每完成一个案例，不只更新策略参数，还要检查通用框架是否需要变化：

1. 是否发现新的数据时间偏差？
2. 是否缺少能够解释策略收益来源的指标？
3. 是否存在回测能表达、实盘无法执行的规则？
4. 是否需要新增某类压力测试？
5. 哪些实验规则可以直接复用于下一类策略？

框架的版本升级应来自这些结构性发现，而不是来自某次回测收益高低。

# 第五部分：建议的第一轮实施顺序

## 29. 阶段一：建立可信研究基础

1. 建立实验登记表和统一实验编号。
2. 固定信号、成交、成本和数据版本记录格式。
3. 增加数据审计报告和暖机期检查。
4. 定义通用基准、风险匹配基准和样本外输出。
5. 将机械回测与经济有效性回测明确标记。

## 30. 阶段二：跑出两个案例的基准

1. 高股息：静态持有基准与现有股息率单锚。
2. ETF：风险匹配被动基准与现有MA轮动。
3. 验证收益、仓位、订单、现金和费用能够完整对账。

## 31. 阶段三：只做单变量研究

1. 高股息只增加成交量密集价，不同时修改股息率档位。
2. ETF只把MA状态替换成 MACD 状态，不同时修改排名和仓位。
3. 分别研究买入、卖出、确认和调仓频率，避免一次加入多个条件。

## 32. 阶段四：组合、样本外和仿真

1. 只组合已经独立通过的组件。
2. 执行滚动样本外、成本、延迟和参数压力测试。
3. 冻结候选版本，进入仿真。
4. 对比仿真成交与回测假设。
5. 达到个人风险门槛后，才考虑极小资金验证。
