# XtData API 自测题

关联主笔记：[[StudyVault - XtData API 速学]]

## 题目

1. `subscribe_*`、`get_*`、`download_*` 三类接口分别解决什么问题？
2. 为什么在调用 `get_*` 前，经常要先执行 `download_*`？
3. `stock_code` 的标准格式是什么？请写出 2 个示例。
4. `period` 里 `1d`、`1w`、`1mon` 各代表什么粒度？
5. 当时间范围很大时，为什么不建议一次性全量请求？
6. 你会如何构建“盘中实时监控”的最小数据链路？
7. `level2` 数据在历史存储和跨交易日使用上需要注意什么？
8. 做板块选股池时，至少要调用哪 2-3 类接口？

## 参考答案

> [!answer]- 1) 三类接口职责
> `subscribe_*` 负责实时推送；`get_*` 负责主动查询；`download_*` 负责下载/补齐本地可查询数据。

> [!answer]- 2) 先下载再获取
> 因为 `get_*` 查询依赖本地可用数据，若本地缺失会返回不完整或空结果；先 `download_*` 能提高查询成功率和一致性。

> [!answer]- 3) 代码格式
> 统一格式为 `code.market`，例如 `000001.SZ`、`600000.SH`。

> [!answer]- 4) 周期含义
> `1d` 是日线，`1w` 是周线，`1mon` 是月线。

> [!answer]- 5) 大范围请求风险
> 容易导致响应慢、超时或内存压力大。建议按时间分片拉取，再拼接处理。

> [!answer]- 6) 盘中链路
> 先订阅 `subscribe_*` 接收实时流，再在回调里计算信号/告警；必要时配合 `get_*` 补查上下文。

> [!answer]- 7) level2 注意点
> level2 偏实时，历史可得性和保留规则与 level1 不同，跨交易日要验证数据是否仍可用。

> [!answer]- 8) 选股池接口组合
> 至少包含板块列表/成分股接口（如板块和成分查询）+ 合约基础信息接口；常再配合交易日历接口对齐日期。
