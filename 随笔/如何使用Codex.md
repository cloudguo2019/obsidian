# 如何使用 Codex

Codex 是一个面向软件工程任务的 AI 编程助手。它可以阅读项目代码、修改文件、运行命令、执行测试，并把修改结果整理成清晰的说明。

## 适合让 Codex 做什么

- 阅读代码库并解释模块、函数、调用链或架构。
- 修复 bug、补充边界条件、改进错误处理。
- 实现新功能，并尽量沿用现有项目风格。
- 编写或更新测试、文档、脚本和配置。
- 做代码审查，指出风险、回归点和缺失测试。
- 运行本地命令，例如测试、构建、格式化、类型检查。

## 一个好请求怎么写

尽量说明目标、范围和验收方式。

```text
请在这个项目里实现用户登录失败重试限制。
要求：
- 同一个账号 5 分钟内失败 5 次后锁定 10 分钟
- 补充单元测试
- 不要改动数据库表结构，优先复用现有字段
```

如果只是想先了解代码，可以明确说“先不要改代码”。

```text
先不要修改文件。请帮我梳理订单创建流程，从 API 入口到数据库写入。
```

## 常用工作方式

### 让 Codex 修改代码

直接描述你想要的结果即可。Codex 会先查看相关文件，再做小范围修改，最后运行合适的验证命令。

```text
修复支付回调重复执行的问题，并补充回归测试。
```

### 让 Codex 做代码审查

可以指定分支、提交或当前改动。

```text
请 review 当前未提交改动，重点看是否有并发问题和测试缺口。
```

审查时，Codex 通常会优先列出问题，再给出简短总结。

### 让 Codex 解释代码

适合快速理解陌生项目。

```text
解释一下这个项目的鉴权流程，并指出关键文件。
```

### 让 Codex 运行命令

可以直接要求运行测试、构建或检查命令。

```text
运行后端测试，并修复失败用例。
```

如果命令需要访问网络、写入受限目录或执行高风险操作，Codex 会请求确认。

## 提高效果的技巧

- 给出具体目标，而不是只说“优化一下”。
- 明确哪些文件、模块或行为不能改。
- 说明项目约束，例如兼容版本、性能要求、接口格式。
- 把大任务拆成可验证的小任务。
- 如果你只想讨论方案，提前说“不要改文件”。
- 如果你希望它继续做到测试通过，明确说“请完成实现并验证”。

## 适合的提示词模板

### 修 bug

```text
这个功能现在的问题是：……
期望行为是：……
请定位原因、修复，并补充测试。
```

### 加功能

```text
请实现……
要求：
- ……
- ……
验收标准：
- ……
- 相关测试通过
```

### 代码审查

```text
请 review 当前改动。
重点关注：
- 是否有行为回归
- 是否有安全或并发风险
- 测试是否覆盖关键路径
```

### 重构

```text
请重构……
目标是……
约束：
- 不改变外部行为
- 保持现有测试通过
- 避免大范围无关改动
```

## 注意事项

- Codex 会尽量保护你已有的未提交改动，不会主动回滚无关文件。
- 对破坏性操作，例如删除文件、重置分支，应该明确说明并确认。
- 对依赖最新信息的问题，例如新版本 API、当前价格、法规或新闻，需要让 Codex 查询最新资料。
- 对高风险任务，例如生产数据库、密钥、资金相关逻辑，要给出更明确的边界和验证要求。

## 推荐流程

1. 先描述你要达成的结果。
2. 让 Codex 阅读相关代码并说明计划。
3. 允许它实现小范围改动。
4. 让它运行测试或构建验证。
5. 查看最终总结和变更文件。

简短地说：把 Codex 当成一个能读代码、改代码、跑验证的工程搭档。请求越具体，结果越稳定。
